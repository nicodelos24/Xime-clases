# Biblioteca visual · Clases v0.1

Base de tamaños y colores: [`tokens.ts`](tokens.ts). Layout de referencia: [`ui.css`](ui.css). Propuesta, **no** componentes React Native implementados. Contratos de interacción/negocio: Fina `02-wireframes.md`, `01-mapa-y-flujos.md`; no se redefinen acá. Mobile first 360×780, min viewport objetivo 320 px; scroll vertical para todo lo que no entre. `fontScale` del sistema hasta 200 %: el texto debe envolver, jamás `numberOfLines={1}` en estado, monto, motivo o fecha crítica.

## Decisiones de contenido y layout

1. «Vence el DD/MM» = **último día cubierto**; «Renueva el DD/MM» = **primer día del siguiente ciclo**. En ficha, Hoy y vista previa mostrar ambas. Si no hay ciclo, no inventar fechas.
2. Uso de UYU con separador local ($ 1.500 UYU) y fecha DD/MM/AAAA cuando se necesita evitar ambigüedad; valores de láminas de muestra, no tarifas. Cifras tabulares. Ciclo de ejemplo se recibe del dominio, **no** lo calcula `CicloPreview`.
3. Las categorías en Hoy son enlace a filtros de Cobros; «Por vencer» es una lista directa adicional. Para «Hoy» y pagos, no mezclar la suscripción que la plataforma cobra al instituto.
4. Pago manual en un paso: «Registrar pago» + alumno/concepto/monto/fecha/medio + vista previa + «Confirmar pago». No procesamiento en app ni factura DGI. Confirmación solo luego de respuesta positiva, comprobante interno con dueño nominal. Anulación en ruta distinta, con motivo, impacto y botón rojo.
5. Asistencia guardada no implica pago: después de marcar clase suelta, ofrecer cobrar o dejar adeudada; vencida jamás bloquea pasar lista. Si la red es incierta no afirmar «Guardada» hasta resolver.
6. WhatsApp muestra «Abrir WhatsApp», no «Enviar aviso». Se edita mensaje antes de salir; al volver, como mucho «Aviso abierto» (sin afirmar envío ni recepción).

## Variantes transversales de alta fidelidad

- **Vacío:** ilustración no necesaria; título corto, motivo y CTA («Todavía no hay alumnos · Agregar alumno», «Nadie por vencer en 7 días»). No disfrazar error como lista vacía.
- **Cargando:** skeleton de dimensiones estables en listas/tarjetas, `aria-busy`; si el CTA necesita vista previa, inhabilitarlo hasta tenerla. Reduced motion = skeleton estático.
- **Offline:** franja de aviso; datos cacheados etiquetados «No actualizados» solo si hay cache real. Pagos, asistencia y cambios de deuda bloqueados sin conexión en MVP. «Reintentar» reusa la **misma** operación identificada; duda de red requiere consulta a servidor primero.
- **Error:** conservar campos; mensaje en la región afectada y reintento explícito, sin inventar confirmación. Conflicto por otra dueña: «Este pago ya se registró; revisá el comprobante» solo si lo confirma servidor.
- **Éxito:** no optimista: «Pago registrado» y comprobante con fecha, medio, concepto y autor. Modal reversible por cierre, pago no editable; anulación separada.
- **Oscuro:** usar tokens semánticos de `oscuro`; evitar opacidad al 50 % sobre texto crítico. Los colores de estado se mantienen por nombre/icono, no por valor hex.

**Pendientes ajenos al diseño visual:** definición Q1–Q5 de Fina y validación de flujos/copys con Ada/clienta; prueba de lector de pantalla, tamaño de letra y manejo real del teclado en una app implementada. Los enlaces/acciones de las láminas estáticas no se pueden probar como flujo.
